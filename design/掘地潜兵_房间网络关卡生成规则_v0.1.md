## 1. 已确认方向与目标

目标体验：降落在初始房间 → 观察空腔与岩层 → 选择连接方向 → 挖开封堵或拓宽裂口 → 进入新的房间 / 甬道 → 分支探索、采矿、形成回路 → 返回交存并撤离。挖掘既能获得矿物，也能扩充玩家当前可探索的空间。

用户已确认：

- 地图由多个房间空腔组成网状连接，同一房间可以连接多个房间。
- 房间之间可以直接相接，也可以通过管状甬道连接。
- 连接处可能被岩层完全或不完全封堵，玩家需要挖掘才能逐步扩展可达区域。
- 房间与连接在水平方向展开，不沿 Z 方向新增上下层房间。
- 房间内允许高低起伏，不可挖外壳也可伸入房间形成固定地形。
- 降落仓必定位于初始房间的某个合法位置，舱门外可能就是岩层。
- 舱门外必须能迈出一步并站稳；这一步之后可以立即遇到需要开挖的岩层，不要求在舱内先挖才能出门。
- 房间之间以预设连接为主，非连接方向由不可挖外壳隔开，不能任意挖穿到邻房。
- 完全封闭的连接及后方房间可以完全没有提示，玩家需要试挖发现；不强制入口特殊材质、裂纹、声音或方向标。
- 延续大片连续岩层与随机团状矿物；部分矿团可以完全隐没、深挖后才发现。

上述关键方向已确认。房间数量、封堵厚度和比例、室内起伏幅度属于后续调参；本文给出的保障与参数建议均另行标明。

### 2026-11-03：每局随机沙盒生成确认

用户确认不制作 Soul: Cave 固定布局。每局生成一个不同的房间网络：降落点位于随机选出的一个合法初始房间，其余房间、连接端口、甬道走向、连接的开/半封/全封状态与空间路径均由本局种子随机确定。地图采用水平网络，房间内部仍可三维起伏；每局必须保证潜在图连通、通用矿镐可逐步打通并可从任务点返回。

首轮建议配置：6–10 间房，潜在图独立回路数 1–3，单房连接度最多 4；保留一个非降落房作为 Boss 房、一个非降落房作为撤离目的地。特殊房间在合格节点中随机选址；连接路径与周围普通房间一同随机生成，Boss 身份和房间职能固定，不随机抽换。降落房和撤离房不能相同；Boss 房可以兼作支线矿区，不可承载唯一任务矿保底。

每局生成须记录 `MissionSeed` 与 `AlgorithmVersion`，同一组合用于复现相同地图；拓扑、岩层形状、矿物与波次方案使用独立随机流，避免增加波次改变房间和资源位置。生成校验有限次失败后换种子，不加载断图、软锁或不可返回地图。以上房间数/回路为首轮白盒范围，后续按地图规模和挖掘时长调参。

本轮只补充设计与示意。原 Demo 的固定 U 形路线、固定六个资源节点仍是现有实现，不能视为已经支持房间网络。

## 2. 地图结构：同一水平层，三维房间内部

### 房间与连接

每个房间有唯一 `RoomId`，包含空腔、可挖围岩范围、不可挖外壳、内部固定地形和若干连接口。房间形状不必规则；大房间可以有凹湾、柱体、坡面和平台，但房间内部必须保留可验证的活动与作业空间。

每条预设连接有唯一 `LinkId`、两个端点房间及两个端口，可选类型：

| 类型 | 空间关系 | 开局形态 |
| --- | --- | --- |
| 邻接连接 | 两个空腔隔着有限厚度的连接区域 | 岩隔墙、部分缺口或已有通口 |
| 管状甬道 | 两房间之间有一定长度的管状空间，可在 XY 平面弯曲 | 内部有空气，入口或中段可能封堵；不要求笔直 |

“连接存在”表示可以沿这一预设方向打通，不表示开局就能走过去。甬道中若有多处堵塞，必须打通全部阻断段才算端到端可通行。

### 水平限制

统一房间连接基准高度 `Zlink`。房间布局点、连接中心线与分支方向在 XY 平面生成；不生成竖井、上下层房间、螺旋下行链或依靠高度错开的跨线桥。

房间内部地板可高低起伏，顶高也可变化；这不等于新增一个地图层级。建议连接口附近回到共同通行高度，局部坡面衔接房间地形。允许的坡度、台阶和净空按实际角色能力验证，不能由“房间同层”推导出“地面必须全平”。

两条甬道在 XY 平面相交时只能：绕行避免交叉，或明确生成可通的交汇节点并纳入连通关系。不能画出不相通的十字交叉，也不能临时用 Z 方向上下跨越。与第三房间意外交叠同样必须拒绝或显式改为连接，不能留成未登记捷径。

## 3. 网络拓扑与探索推进

地图同时维护三种关系，不能混为一谈：

| 关系 | 含义 | 用途 |
| --- | --- | --- |
| 潜在连接图 `Gpotential` | 所有合法可打通连接 | 保证整张生成地图有解 |
| 当前通行图 `Gwalk(t)` | 此刻存在完整角色通道的连接 | 行走、返回与当前可达空间 |
| 玩家发现记录 `Discovered(t)` | 玩家实际看到或进入的区域 / 入口 | 后续地图显示；不等于全局生成器信息 |

建议先构造覆盖所有房间的连通骨架，再添加若干合法连接形成回路。允许有死路资源房，但不能所有房间仅排成一条链；“网状”首版建议至少有一个有效回路和一个多出口房间。具体房间数和回路密度属于调参。

`Gpotential` 从初始房间必须能到达全部生成的探索房间。`Gwalk(0)` 可以只包含初始房间，所有出口都被岩层封住也是合法开局，只要有能从当前站位开始、使用通用矿镐完成的打通过程。

应进一步验证几何空间的可达连通分量：一个大房间若被不可挖平台或剩余岩层分割，不能仅因 `RoomId` 相同就把所有端口都算成可达。房间图是摘要，角色胶囊的实际路径才是最终依据。

每次挖掘后，只有形成足够净空与脚下支撑的通道才加入通行图。看见下一房间、射线穿过小孔、能开枪命中对面，都不能代替“角色能走过去”。新打开一个入口可能一次接通多个原本互通的房间，但玩家发现记录仍按观察 / 探索更新。

## 4. 外壳、围岩和房间内起伏

### 统一空间归属

建议先为每个房间规划可活动空腔及足够厚的挖掘包络，再用预设连接体积把它们连接起来，形成有限可挖域 `D`。包络厚度是留给挖矿与拓宽的空间，不是不可挖外壳本身。

```text
D = 各房间挖掘包络的并集 ∪ 各预设连接的挖掘包络
Bedrock = D 外侧封闭壳层 ∪ D 内部的固定地形实体
Air0 = ((房间初始空腔 ∪ 甬道初始空气) ∩ D) − (连接封堵 ∪ Bedrock)
Rock = D − Bedrock − Air0 − Ore
Reach0 = Air0 中能从玩家出生点以合法角色姿态到达的部分
```

这些集合都按实际占用离散并互斥归属；不可挖外壳之外不可进入。`Air0` 包含尚未抵达的后续房间空气，不能全部当作开局可达空间。上述公式是组织关系，实际生成还要校验封堵、端口和碰撞。

关键约束：

- **外壳包围的是房间空腔及可挖围岩，不是紧贴每一处可见墙面。**否则无法容纳此前要求的深埋矿。
- 两个房间非连接方向的挖掘包络不能相通，即使俯视距离很近也要有连续不可挖隔层；检查侧面、顶部、底部及拐角，防止绕挖。
- 连接口处预先打通不可挖壳层的接口，再用可挖岩层封堵。甬道周围同样有不可挖包覆，甬道内部不能残留独立房间外壳形成双层永久墙。
- 全部可挖岩石和矿石移除后，玩家仍不能离开有限地图或通向未生成空间；不依靠可破坏物承担最终封边。
- 岩层噪声、房间噪声和运行分块不能改变已确认的拓扑，不能随机切出连接外的孔洞或堵回必需端口。

### 内部固定地形

不可挖地形可形成起伏地板、岩台、缓坡、岩脊和支柱。建议从外壳 / 地基向内部延伸，维持稳定支撑；不默认引入坍塌。

先确定各端口、出生、交存等必要站位与连接路径，再在剩余空间内形成固定地形。固定地形不得占据关键路径所需的净空，不得把房间截成无解的两个区域；局部高台可作为可选区域，任务保底资源不放在只有特定职业才能抵达的位置。

通用路径需同时检查上坡和返回方向。落差可跳下但无法原路返回、斜坡可视但超出行走坡度、天花板过低、平台边缘可站但转身碰撞，都判为问题。高低变化幅度暂不固定数值，先使用实际角色坡度、台阶、胶囊与镜头参数约束。

## 5. 封堵状态与挖通判定

视觉形态与通行状态分别记录：

| 连接状态 | 空气 / 岩层形态 | 玩家行为 |
| --- | --- | --- |
| 完全封闭 | 封堵覆盖连接横截面，没有贯穿空气路径 | 先挖穿，再拓宽到可走 |
| 不完全封闭、不可通行 | 有裂缝或孔洞，但角色完整通道不存在 | 可能看到对面，仍需拓宽、增高或修整地面 |
| 不完全封闭、可通行 | 有角色能穿过的缺口，周边仍有岩层 | 可先进入，也可继续扩宽 |
| 已开放 | 连接已有完整通行截面 | 无需挖掘即可通过 |

不使用“挖掉百分之多少”或“打破一块”作为唯一开门条件；以真实碰撞与路径为准。某一侧挖穿只是局部事件，甬道另一处未打开时，后方房间仍不能算可达。

封堵厚度与矿团埋深分开调参。门口岩堵决定探索推进成本，深埋矿决定可选开采成本，不能直接把 5–12 m 深矿档套给每道连接。建议首个必经岩堵较薄，后续按路径累计工作量安排，具体耗时待正常工具实测。

封堵可以含矿，但不能每道都有矿、不能强制用开采任务矿才能释放关键操作。围岩与矿仍互斥，每矿团独立产量账本。挖开连通口不自动奖励整团矿物。

连接发现方式已确认：完全封闭的连接与后方房间允许没有任何提示，需要玩家试挖。封堵不强制采用特殊材质、方向箭头、光线或声音暗示；普通可挖围岩可以没有后续房间，不能形成“可挖表面一定通向新房”的隐含保证。若实际挖出孔洞，则按真实视线显示后方空间；这是挖掘后的发现，不是开局透视。

不可挖外壳应在受到攻击时提供与可挖岩不同的反馈，避免玩家无限攻击无效边界；这只表达当前命中材质，不扫描外壳后面是否有房间。策划全图与连线仅供调试，不能直接作为玩家地图。

## 6. 初始房间与降落仓

初始房间由生成器明确指定，降落仓位置从其合法候选位中选择，可以在中央、近墙或凹湾；“随机位置”不意味着可以与地形任意穿插。

所有候选都要满足：

1. 舱体完整占位、门的运动空间和玩家出生胶囊不与岩层 / 外壳重叠。
2. 有可靠地面与顶高，不能悬空、嵌入不可挖平台或把舱门朝向无解外壳。
3. 门外近处是岩层也可以，但必须存在可用通用矿镐逐步打通的出舱路线，不依赖有限弹药、钻机燃料或其他职业。
4. 矿镐射线、镜头和碰撞实际允许从起始站位作业；不能只有关卡图上“可挖”而工具打不到。
5. 如果舱体成为阻挡，另一侧仍可保留返回 / 交存通行空间；不随机封死已规划的必要端口。

已确认门外保留一步安全站位。将舱体、门运动范围及这一步站位定义为必须留空的 `ExitSafeVoid`，其尺寸按角色胶囊、落脚面和门实际运动范围推导；站位之外允许紧接可挖岩层。角色可先正常出舱站稳，再从这一站位挖掘；不得让角色出生在岩石中，也不得自动清掉整片封堵来掩盖失败的出生布局。

降落演出与不可挖顶壳要分开处理。沿用现有短过渡方式是低成本建议；若后续制作完整下降演出，应使用预留且不可进入的降落接口及封闭处理，不让仓体“钻穿不可挖外壳”成为玩家也可沿 Z 扩图的规则。撤离舱是否回到初始位置并未在本次确认，保持独立候选规则。

## 7. 矿物、补给与关键路线

矿物在空腔、连接、封堵和不可挖地形完成后放置。使用矿团原形状算法；深矿只能放入有足够厚度且可采尽的围岩，不能放入不可挖外壳或固定地形中。

**修正旧“主路始终畅通”：**新地图的任务保障路径可以经过需挖掘的连接；它要求使用通用工具最终可达，不要求开局全程是空气。保底不能依赖某一职业、一次性炸药或必须先找到的隐藏矿物。

原 300 晶矿 / 240 硝石、主目标 200、主路线晶矿至少 240 / 硝石至少 160，以及首段 80 硝石暂保留为预算基线。需要重新映射到房间网络，不继续机械使用旧的六区编号。

用户已选择连接可以完全无提示，因此“生成器知道能挖到”与“玩家能及时发现”必须分开验收。240 / 160 的通用工具可采量不等于实际可发现量，不能继续承诺原先 10–15 分钟目标自然成立。

首段补给建议调整空间分配：把至少 80 硝石放在初始房间内的可见 / 露头采集区，玩家完成出舱作业后可探索取得，不要求先猜中隐藏连接；总量仍为 240。该分配是保障补给的新建议，未修改正式配置。其余矿物可以位于后续房间；记录空挖距离、首次发现连接与补给耗时，再判断是否需要调整密度和厚度，不擅自加入寻路提示。

深埋矿保底口径继续采用建议：无定位的完全隐藏矿暂不计入可发现资源。新网络下另区分：

- 矿团到任意初始房间空气的局部覆岩厚度 / 局部挖掘代价，用于矿体浅深分类。
- 从出生点到该房间的连接开通成本，用于整局探索节奏。

不能因为表面矿所在房间有三道厚封堵，就把这个表面矿标成“深埋矿”；也不能只从出生空气计算距离，漏掉尚未进入的房间背面距离矿体仅 0.5 m 的捷径。

运输机器人、敌人和撤离的路径必须适配当前已打开的通道。首版建议交存点和撤离候选位使用已验证可达空间；新开放小孔不代表机器人也能通过。当前固定路线 AI 尚未支持动态房间网络，属于后续实现成本，不在本轮扩写新 AI 机制。

## 8. 生成顺序与约束

```text
读取种子、房间预算、水平范围、角色能力与资源预算
生成 XY 房间候选布局，预留空腔及足够厚的挖掘包络
建立可路由的邻接候选 → 选连通骨架 → 添加合法回路
确定初始房间、连接口与直接 / 甬道类型
联合构造挖掘域与不可挖外壳，检查非连接方向隔离
构造房间空腔、甬道与内部固定起伏，保留最终通行净空
选择降落仓与必要站位，检查出舱可挖路线
生成连接封堵、连续围岩与局部空气裂口
检查初始可达区域和逐步打通全部房间的可行过程
按推进顺序分配资源保底，再放置露头矿与深埋矿
复查几何、通行、深度、预算、交存与撤离
生成稳定编号和逻辑分块，验证成功后提交本局
```

“最终通行净空”是挖开之后必须能形成的路径，允许初始填有可破坏封堵；“初始安全留空”才是生成时必须扣除岩层的空间。若将两者混为同一保护掩码，封堵会在生成时被自动清掉，导致挖掘扩图玩法失效。

候选放置、连线和封堵生成都要有限重试；局部失败优先重选端口、重排甬道或调整候选房间，再尝试下一地图种子。若必须取消房间，需同步重分资源并复查回路与任务预算，不能留下悬空连接或吞掉矿量。重试全部耗尽则返回明确失败，不加载一张“可能挖不通”的地图。

随机流分别用于布局、连接、空腔形状、封堵、固定地形和矿物。种子、配置与算法版本共同决定结果；分块加载顺序不改变房间、矿团或封堵。

### 首轮参数建议

| 字段 | 类型 / 单位 | 建议或约束 |
| --- | --- | --- |
| `RoomCount` | 整数 / 间 | 可先用 7 间代表样例，再评估 6–10 间；不是已确认关卡规模 |
| `MaxRoomDegree` | 整数 / 条连接 | 建议 4；至少一间连接数 ≥3；空间不足须重排，不强挤入口 |
| `CycleCount` | 整数 | 连通无向图独立回路数 `E − V + 1`，建议 1–3；几何必须实际可打通 |
| `LinkType` | 枚举 | 直接相接 / 管状甬道 |
| `SealState` | 枚举 | 全封 / 半封不可行 / 半封可行 / 开放；比例待试玩，不强制平均 |
| `SealThickness` | 浮点 / m | 与深矿埋深独立；按最短可行打通路径及有效横截面校验 |
| `LinkClearance` | 浮点 / m | 由胶囊直径、全高与安全余量推导，不按视觉裂缝宽度判断 |
| `FloorSlope / StepHeight` | 度 / m | 不超过当前角色支持值；单独验证返回方向 |
| `ShellThickness` | 浮点 / m | 覆盖占用精度、碰撞误差和所有边界，禁止单元级漏缝 |
| `PodCandidateTries / MapTries` | 正整数 / 次 | 有限上限；正式初值在实现前配置，不使用无限循环 |
| `Seed / AlgorithmVersion` | 整数 / 版本标识 | 连同配置记录，支撑复现与回退诊断 |

净空示例公式：`最小净宽 = 2 × 胶囊半径 + 2 × 横向余量`；`最小净高 = 2 × 胶囊半高 + 顶部余量`。采用离散单元时向上取整，`格数 = ceil(净空 / 单元尺寸)`，不向下取整压缩角色通路。弯道、斜坡和第三人称镜头另做实际检查，不能只用直线矩形尺寸代替。

## 9. 玩家操作样例与验收

示例：玩家降落在 S 房间，两个出口分别是全封岩堵与只剩窄缝的半封入口。先挖宽窄缝到能通行，进入 B；B 与 D 之间原本已有开放甬道，因此当前可达空间同时包含 S、B、D。再从 D 打通 E，随后打开 E 通向 C 的入口，与另一条路线构成回路。C 房内有不可挖高台，矿镐不能削平台，但旁边可挖围岩能形成支路并发现深矿。整个过程在同一地图层，房间内允许坡面起伏。

验收清单：

1. 潜在图全连通、有约定回路和多出口房；无竖向房间链、悬空端点或未登记交叉。
2. 非预设连接方向挖尽仍被外壳阻断，预设连接不存在双层不可挖墙；顶部、底部与分块边界封闭。
3. 完全封堵、窄缝、可走缺口分别正确分类；甬道多段封堵不能提前标为贯通。
4. 岩层局部移除后按角色实际净空更新可达空间，不能用射线通或房间编号替代通行。
5. 全出口封堵的初始房间仍可从合法站位使用通用矿镐打开；出舱朝墙、角落落舱、坡地候选均无软锁。
6. 固定起伏不破坏必要站位、入口、上下坡与返回，必要资源不依赖职业高台路线。
7. 未发现房间不能通过调试标牌、全局示意或资源 UI 泄露；真实玩家地图揭示规则需独立实现。
8. 复算总资源与推进阶段保底；矿物不落入外壳；深矿同时检查邻房背面与内部空腔。
9. 挖掘、分块重载、暂停和重开不重置已挖空间、不重复发矿；连接状态由有效几何恢复。
10. 未来实现后至少批测 100 个种子，并对代表图验证枪手 / 钻机手出舱、完整探索、返回交存、敌人寻路和撤离；记录失败种子与修复，不把二维示意当作真实游戏验收。

当前只完成设计。地图房间数量、封堵比例与厚度、内部地形幅度、首次开路与补给耗时尚未实测。
